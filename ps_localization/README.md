# PS端方位角与近场距离估计

## 实际布局和角度约定

用户2026-10-21确认：边长约7cm，1左上、2右上、3右下、4左下，声源大致与阵列同平面。

随后确认串行线/槽位：麦1=第一条SD左，麦2=第一条SD右，麦3=第二条SD右，麦4=第二条SD左。RTL端口名字 `SD` 对应第一条线（BD的SD_0/T9），RTL `SD1` 对应第二条线（BD的SD1_0/U10）。I2S输出已按物理麦编号统一，第二条线需要 `data3=r_data1[47:24]`、`data4=r_data1[23:0]`；PS坐标不用交换。

```text
                前方 +Y / 0°
         麦1 ──────── 麦2
          │    中心    │             右方 +X / +90°
         麦4 ──────── 麦3
                后方 ±180°

左方为 -90°；距离从阵列中心计算。
```

麦克风坐标单位为米：1=(-.035,+.035)，2=(+.035,+.035)，3=(+.035,-.035)，4=(-.035,-.035)。
`localize_2d.h` 的 `LOC_SIDE_M` 可修改实际边长；若不是正方形，应修改 `localize_2d.c` 中四个麦克风坐标，不能继续使用正方形坐标。

## 已实现的PS流程

保留已有GPIO整批读取、批次编号核对和原始lag串口打印。每批数据到达后：

1. 检查valid、IFFT帧错误、物理最大时延、有效麦克风对数量。
2. 根据同平面球面传播模型，搜索声源方位角及到阵列中心的距离。
3. 用六组时延的预测误差做最小二乘拟合。
4. 检查候选解的方向与距离是否存在明显歧义。
5. 有效方向打印角度；距离能分辨时打印估计和候选范围，否则打印 `range=UNRESOLVED`。

模型为：

```text
预测lag_ij(x,y) = (到麦i的距离 - 到麦j的距离) × Fs / c
误差 = 有效麦克风对的 (预测lag - 实测lag)² 的平均值
```

TDOA球面模型及其远场平面波近似可参考[Microsoft Research论文第2页式(1)、(2)](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/Microphone20Array20Processing20for20Distant20Speech20Recognition20-20Towards20Real-World20Deployment.pdf)。远场近似的时延主要依赖方向；不能用 `lag*c/Fs` 作为声源到阵列的距离，那只是两条传播路径的长度差。

## 为什么距离可能未确定

当前PL输出整数采样点时延。44100Hz、声速343m/s时，一个采样点相当于约7.78mm的路径长度差。
对7cm小阵列，多个距离可能产生同一组整数时延；程序不能把搜索得到的某一个最小值直接当成可靠距离。

因此代码保留误差接近最佳解的一组候选点，按0.5个采样点的量化容差检查歧义：

- 候选方向跨度超过40°，不输出确定方向。
- 候选距离触及搜索边界、包含远场解，或上下界相差超过2倍，输出 `range=UNRESOLVED`。
- 其余情况下输出 `range_est_cm` 与 `range_band_cm`。

这里的候选范围是模型和人为门限下的网格支持集，**不是统计置信区间，也不包含全部麦克风位置误差、混响误差与高度误差**。0.5点门限同样不是对GCC误差的保证。
模型有限距离搜索为2.5cm～3m，64个对数半径、180个方位（步进2°），另加入显式远场候选，防止把远场声源强行估成3m。2°是搜索步长，不是实际测角精度。
距离输出很可能只在非常近的声源和较好数据下出现。要扩大可靠测距范围，需要进一步提高时延精度、阵列孔径或加入额外测距信息；当前实现不声称可可靠测出任意距离。

## SDK接入

- `main.c`：替换应用的原入口文件内容，实际工程仍叫 `helloworld.c`，只保留一个main。
- `localize_2d.c/.h`：加入同一个应用src目录。
- `lag_packet.h`：继续使用已有头文件。
- 应用根目录 `makefile.defs`：给数学运算加入libm，避免sqrtf、sinf、cosf、powf链接失败。它是用户扩展文件，不修改SDK生成的makefile。

安装脚本 `install_sdk.ps1` 会先备份当前SDK源码再复制以上内容。当前工程为 `D:/FPGA/heelo_world/heelo_world.sdk/mic_app2`。
安装后在SDK中对mic_app2按F5刷新，再Build；建议使用Release或-O2编译以缩短计算时间。程序上电会先生成查找表，使用约324KB DDR静态存储，不放在8KB栈中。

串口示例（格式演示，不是板级实测）：

```text
... azimuth_deg=90 range=UNRESOLVED fit_milli_sample=120
... azimuth_deg=90 range_est_cm=4 range_band_cm=3..5 fit_milli_sample=33
... azimuth=UNRESOLVED range=UNRESOLVED reason=INCONSISTENT_TDOA
```

`fit_milli_sample=120` 表示预测时延的RMS误差约0.120个采样点，不是距离误差。
保持原UART波特率；xil_printf不需要浮点格式，角度和厘米转换为整数打印。

## PL还有一处必要修正

先前布局假设把14、23当对角线；实际应为 **13、24**。
已修改工作区引用的 `phat_ifft/PHAT_IFFT_Ctrl.v`：`work_pair==1 || work_pair==4` 使用±13点，其余对使用±9点。

Vivado中刷新PHAT模块引用、Validate、重新生成并下载bitstream。端口没有变化，现有连线不需重画。
不更新bitstream时，13、24的时延仍可能被错误限制在±9点，导致后续角度/距离拟合错误。
